# Рабочее место — бот и веб-приложение для персонала ресторана

Один Node.js-сервер: Telegram-бот (grammY) + мини-приложение/сайт (папка `webapp`) + SQLite.
Работает и внутри Telegram, и как обычный сайт в браузере (вход по телефону и паролю).

## Возможности
- Зарплата и аналитика по двум расчётным периодам: 1–15 число (выплата 25-го) и 16 число — конец месяца (выплата 10-го следующего месяца), плюс вид «Весь месяц» и переключение месяцев. Аналитика сравнивает период с предыдущим; суммы денег видит только владелец.
- Обучение: сотрудник отмечает материалы изученными, менеджер/владелец видит прогресс каждого сотрудника и по каждому материалу.
- Чек-листы: можно назначить на должности; ежедневное выполнение. Отчёт менеджера: кто, какие задачи и во сколько выполнил (по сотрудникам и по задачам), навигация по дням.
- Интерфейс в стиле iOS: крупные заголовки, группированные списки, стеклянная панель вкладок, кольца и полосы прогресса, плавные анимации.

## Интерфейс на ноутбуке
От 900 px шириной приложение показывается как веб-панель: слева боковое меню (вкладки, разделы по роли, карточка пользователя), справа широкая рабочая область. Главная и карточки в две колонки, аналитика с четырьмя показателями в ряд, график команды на всю ширину. На телефоне и в Telegram остаётся нижняя панель.

## Роли и доступ
Роль определяется должностью при добавлении сотрудника. Роли «Администратор» нет — только «Менеджер».

| Должность | Что делает |
|---|---|
| Владелец | всё, все филиалы, суммы зарплат |
| Менеджер | свой филиал: сотрудники, заявки, объявления, обучение, чек-листы, аналитика; график для всех, включая тех персонал |
| Финансовый директор | видит график всех, составляет график кассирам, аналитика по всем филиалам с суммами (назначает только владелец) |
| Шеф-повар | видит и составляет график поваров |
| Бар-менеджер | видит и составляет график барист и барменов |
| Остальные (официант, хостес, кассир, повар, бариста, бармен, тех персонал) | свой график, приход/уход, зарплата, обучение, чек-листы |

Филиалы: «Ещё» → «Филиалы» (владелец и финансовый директор). При добавлении сотрудника выбирается филиал; менеджер видит только свой, владелец и финансовый директор — все и сравнение между ними в аналитике.

## Деплой на Render

1. Залейте содержимое папки в GitHub-репозиторий.
2. Render → New → Web Service → выберите репозиторий.
   - Build Command: `npm install`
   - Start Command: `npm start`
3. Environment Variables:
   - `BOT_TOKEN` — токен от @BotFather
   - `SESSION_SECRET` — любая длинная случайная строка
4. Deploy. Адрес сайта Render подставит сам (`RENDER_EXTERNAL_URL`), webhook бота и кнопка меню «Приложение» настроятся автоматически.
5. В @BotFather → ваш бот → Bot Settings → Menu Button / Mini App можно указать тот же адрес.

### Важно про базу данных
На бесплатном плане Render файловая система временная: при каждом перезапуске и деплое файл базы
сбрасывается к `seed/database.db`. Чтобы данные не пропадали:
- подключите Persistent Disk (платный план) и задайте `DATABASE_PATH=/var/data/database.db`, либо
- переехать на PostgreSQL (потребует доработки слоя `lib/db-adapter.js`).

## Вход
- Владелец: телефон `+998904760501` и ваш пароль — в браузере, и в боте командой `/login`.
- Сотрудники: телефон и пароль, выданные менеджером.

## Локальный запуск
```
npm install
BOT_TOKEN=... npm start
```
Без `BOT_TOKEN` запустится только веб-часть. Откройте http://localhost:3000.
